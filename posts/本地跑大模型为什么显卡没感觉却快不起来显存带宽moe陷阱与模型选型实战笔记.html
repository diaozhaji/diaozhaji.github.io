本地跑大模型为什么显卡没感觉却快不起来——显存带宽、MoE陷阱与模型选型实战笔记

📅 2026-09-26  ·  🏷️ 大模型 · GPU · 显存带宽 · MoE · 模型选型 · 本地部署

从 3060 实测 50 tok/s 出发，讲清 LLM 推理的瓶颈到底在哪：带宽、MoE 的真相，以及"编程/Agent 该选什么模型、配什么卡"。

1. 一个典型困惑

我有一台台式机：5700X + 8G 内存 + RTX 3060 12G + 1T 硬盘。本地跑 9B 级模型，任务管理器显示内存快满了，但"3D"那一栏 GPU 使用率只有 9%，而显存用了 7.4G/12G，速度约 50 token/s。

直觉上"显卡没在干活"？其实正好相反——显卡一直在满负荷，只是你看错了指标，而且瓶颈压根不在算力上。

2. 核心结论：LLM 生成速度 ≈ 显存带宽 ÷ 模型权重大小

LLM 每生成一个 token，都要把模型的全部权重从显存搬运到计算核心做一次矩阵乘法。也就是说：

  • 每出一个字 = 完整读一遍模型权重
  • 速度 = 显存带宽能搬多少 ÷ 权重有多大
decode 速度 ≈ 显存带宽 ÷ 每 token 读取的权重大小

实测验证：3060 带宽 360 GB/s，跑 9B Q4（权重约 5.5GB），理论上限 360÷5.5 ≈ 65 tok/s，实际 50 tok/s，效率约 77%——合理。

这就是为什么显卡越跑越快跟"算力"关系不大，瓶颈在"搬货的速度"（带宽）。游戏卡拼算力，LLM 卡拼带宽。

3. "3D 栏 9%"是错觉，LLM 走的是 Compute

Windows 任务管理器 GPU 那一栏展开后有多个引擎：3D、Copy、Compute、Video。LLM 推理走 CUDA 计算核心，对应的是 Compute 栏；3D 栏是图形渲染管线，跟推理无关。

看真实利用率请用：

nvidia-smi        # 看 GPU-Util % 和显存占用
GPU-Z / HWiNFO    # 各引擎实时利用率

另外，单用户聊天是"逐 token 生成"，GPU 忙几十毫秒就闲下来等输入，平均利用率本来就不高；而 prefill（处理你输入的那段）是计算密集的，会把 CUDA 拉到 90%+，你看到的"95%"大概率就是它。

4. 为什么系统内存会"满"

8GB 物理内存跑模型本来就小。三个叠加原因：

  1. Windows + 后台程序本身就吃掉 3-4G
  2. 模型没有 100% offload 到显存时，部分层权重驻留系统内存
  3. Windows WDDM 会在系统内存里给独显预留"共享显存"预算（12G 卡通常留 6~7G 的虚拟共享池）

加内存提升的是整机流畅度和能加载更大模型，但几乎不影响 token/s（decode 速度由显存带宽决定）。

5. 主流显卡"跑 LLM 的价值"对比

卡 显存 带宽 备注
RTX 3060 12G 12G 360 GB/s 9B Q4 ≈ 50 tok/s，够用但带宽低
RTX 3080 12G 12G 912 GB/s 带宽 2.5 倍，但 12G 装不下 27B Q4
RTX 3090 24G 24G 936 GB/s 27B Q4 ≈ 60 tok/s，个人跑 27B 性价比甜点
RTX 4090 24G 1008 GB/s 比 3090 略快，贵得多
5090 笔记本 24G ~1500 GB/s 快但整机 2.5 万+，不值
DGX Spark 128G 统一内存 273 GB/s 容量巨大但带宽低，跑 27B 反而只有 ~18 tok/s

结论：想流畅跑 27B 级稠密模型，24G 显存起步；性价比路线就是二手 3090 + 850W 电源。

6. MoE 能"又快又大"吗？——快，但分场景

MoE（混合专家）总参数大、每次只激活一部分专家：

  • decode 速度看激活参数：Qwen3-30B-A3B（总 30B/激活 3B）Q4 权重 18GB，但每个字只搬"激活 3B + 共享层"，理论速度 936÷2.8GB ≈ 300+ tok/s，实际 100-150
  • 显存占用看总参数：专家得全放显存，24G 才装得下
  • prefill 和共享层仍是稠密的，不省算力

但"快"不等于"强"：编程/Agent 这类任务需要单步深度推理（长链条上下文、跨文件逻辑），激活参数只有 3B 的 MoE 每次"同时在线"的脑容量太小，实战编程远不如同代的 27B 稠密模型。

7. 编程/Agent 场景：27B 稠密 vs 30B MoE 的正式评分

拿官方数据说话（来源：千问官方、公开评测）：

指标 Qwen3.8-27B（稠密） Qwen3-30B-A3B（MoE）
SWE-bench Pro（真实 Issue 修复） 61.7（超 Claude Opus 4.6 Max 的 53.4） 上一代通用档，明显更低
Agent 智能指数 52（对标 GPT-5.6 Luna / DeepSeek V4 Flash） 无同源亮眼数据
OSWorld-Verified（电脑操作） 84.3 —
多模态 Agent 原生（视觉→操作） 不支持
架构 稠密 27B，全量激活 MoE，激活仅 3B

结论：编程和 Agent 能力，27B 稠密是碾压级，且有正式评分背书。MoE 的速度换不来编程的准。

8. 轻量档：Gemma 4 E4B（我本地也在跑）

  • 总参数 8B，有效参数 4.5B（"E"=Effective，Per-Layer Embeddings 技术），42 层，128K 上下文
  • 不是经典 MoE，是"每层嵌入复用"降有效参数
  • 定位端侧/轻量：聊天、轻量文本、OCR、语音

3060 跑它的理论上限（按量化位）：

量化 理论 实际预期
Q4 ~160 tok/s 110-130
Q8 ~80 tok/s 60-70
FP16 ~40 tok/s 30-35

9. 最后的选择建议

用途 推荐组合
本地轻量问答/文本 3060 够了，跑 Gemma 4 E4B Q4（100+ tok/s）
编程 / Agent / 27B 稠密 3090 24G + 850W 电源，跑 Qwen3.8-27B 量化版（~60 tok/s）
只想更快的小模型 3090 跑 30B-A3B 可达 100+ tok/s（但编程弱）
追求模型上限 直接上云端 API（DeepSeek/Qwen 端点），比本地买卡划算

一句话：带宽决定速度，激活参数决定"快不快的上限"，但稠密模型决定"难任务的下限"。 编程/Agent 选 27B 稠密 + 24G 显存，这是个人电脑跑大模型最务实的解。
